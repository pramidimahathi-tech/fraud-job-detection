Can a model spot a fake job posting?

ES 335 ML project. A logistic regression reads a posting's text, details and company signals and estimates how likely it is to be fraudulent. Scroll through the method, or jump to Try it and test your own posting.

Question

Can we predict whether a job posting is fraudulent using only what is visible on the posting? Each row is one posting; the target is fraudulent (1 = fraud, 0 = genuine). Inputs are the title, description, requirements, five category fields and three yes/no flags (company logo, screening questions, company profile).

The claim is limited: this ranks postings by suspicion for a human to review. It does not prove fraud, and it was trained on one dataset of older postings.

Data

The data is the public Kaggle Real / Fake Job Posting Prediction dataset: 17,880 postings and 18 columns, of which 866 (4.84%) are fraudulent. It is not stored in this repo; download it from Kaggle.

Quality checks. Several columns are mostly empty: salary range 84% missing, department 65%, required education 45%, benefits 40%. Duplicates are a problem: 281 rows are exact copies, and 1,932 more share the same title, description and requirements. No duplicate group had conflicting labels.

Preprocessing

  • Remove duplicates first (same title, description, requirements), leaving 15,948 postings with 688 frauds (4.31%). Otherwise the same posting could sit in both training and test data and inflate scores.
  • Drop weak columns (ID, location, salary, department, benefits, telecommuting). Their mutual information with the label was near zero, except country (0.018), which we left out for simplicity.
  • Fill gaps: missing categories become "Missing" (itself informative); missing text becomes empty. A has_company_profile flag keeps the signal from the dropped profile text.
  • One text field: title, description and requirements are joined, then turned into TF-IDF scores (5,000 words, English stop words removed, words in at least 5 postings), which up-weights words that are common in one posting but rare overall. Categories are one-hot encoded; flags pass through.
  • Split before learning: stratified 80/20 train/test split (12,758 train with 550 frauds; 3,190 test with 138 frauds). TF-IDF and encoders live inside a pipeline, so they are re-fit on training folds only and never see validation or test rows.

Baseline and methods

Baseline: always predict "genuine". It scores 95.7% accuracy but catches no fraud (recall 0), so any real model has to beat it on recall, F1 and PR-AUC rather than accuracy.

Model: logistic regression with class_weight='balanced', because fraud is rare. It suits sparse text features, trains fast, and each word gets a weight we can read, which powers the explanations on this page. We tuned the penalty (L1 or L2) and strength C (0.01 to 100) with 5-fold stratified cross-validation scored by PR-AUC. The best setting was L2 with C = 10.

Evaluation

Tuning and final testing are kept apart: the grid search used only the training set with 5-fold stratified CV (same folds for every model), and the test set was scored once at the end. Stratification keeps the 4% fraud rate in every fold.

Because only about 4% of postings are fraud, accuracy is misleading. We lead with PR-AUC (ranking quality for the rare class), recall (frauds caught) and precision (flags that are right), and report F1 and ROC-AUC as summaries. Bootstrap intervals (1,000 resamples of the test set) show how uncertain the numbers are.

      Errors

      At threshold 0.5 the model makes 71 false alarms and misses 26 frauds. Load them above with the "False alarm" and "Fraud missed" buttons.

      • False alarms: the highest-scoring genuine postings (up to 99%) mostly have no company logo or profile, which the model treats as strong fraud signals.
      • Missed frauds: postings like "Sir Awesome" and a home-care nursing ad read like ordinary jobs, and their text and company signals look normal.

      Limitations

      • One dataset from one source, collected years ago; scammers change tactics, so results may not carry over to today's postings.
      • Only 138 test frauds: the intervals are wide (recall could be 0.75 to 0.87).
      • The model leans on logo and profile flags and on industry words (oil, gas, subsea), which may reflect how this dataset was collected rather than fraud itself.
      • Precision is about 0.6, so flags need human review. Duplicates were removed by exact text match; near-duplicates may remain.

      Conclusion

      A tuned, class-weighted logistic regression clearly beats the always-genuine baseline (PR-AUC 0.81 vs 0.04, recall 0.81 vs 0) and is easy to explain. It is useful as a triage tool, not as a final judge. Next steps would be near-duplicate removal, adding country, and testing on newer postings.

      Reproduce

      1. Download fake_job_postings.csv from Kaggle (link above).
      2. Install the packages: pip install -r requirements.txt (scikit-learn 1.6.1).
      3. Run ML_project_data_analysis.ipynb top to bottom (random seed 42 everywhere). The last cell writes model.json and examples.json; the earlier test cell writes test_scores.csv and fraud_model.joblib.
      4. Preview the site: run python -m http.server in this folder and open localhost:8000.

      The raw dataset and API keys are not committed. Only load .joblib files you trust.
