Question

Can we predict whether a job posting is fraudulent using only what is visible on the posting? Each row is one posting; the target is fraudulent (1 = fraud, 0 = genuine). Inputs are the title, description, requirements, five category fields and three yes/no flags (company logo, screening questions, company profile).

When is the prediction made? When a posting is first read, before anyone applies. Only information on the posting itself is used, nothing about applicants, replies or outcomes.

The claim is limited: this ranks postings by suspicion for a human to review. It does not prove fraud, and it was trained on one dataset of older postings.

Data

The data is the public Kaggle Real / Fake Job Posting Prediction dataset, which comes from the Employment Scam Aegean Dataset (EMSCAD, University of the Aegean): real postings collected in 2012 to 2014. It has 17,880 postings and 18 columns, of which 866 (4.84%) are fraudulent. Access: free download with a Kaggle account; it is not stored in this repo.

Each row is one job posting

Key variables. Text: title, description, requirements. Categories: industry, function, required education, required experience, employment type. Yes/no flags: company logo, screening questions, company profile. Target: fraudulent.

Which variables matter most. Mutual information with the label on training rows: industry 0.029, has_company_profile 0.025, has_company_logo 0.023, function 0.013, the rest lower. Words most strongly tied to the label by chi-square include subsea, aker, hse, cash, earn and oil (the Try it section shows which way each word pushes).

Quality checks. Several columns are mostly empty: salary range 84% missing, department 65%, required education 45%, benefits 40%. Duplicates are a problem: 281 rows are exact copies (ignoring the ID), and counting postings with the same title, description and requirements, 1,932 rows repeat an earlier posting. No duplicate group had conflicting labels.

Preprocessing

  • Remove duplicates first (same title, description, requirements), leaving 15,948 postings with 688 frauds (4.31%). Otherwise the same posting could sit in both training and test data and inflate scores.
  • Drop columns that are mostly empty or weak (ID, location, salary, department, benefits, telecommuting; the company profile text is dropped too, see below). Salary range (84% missing) and department (65% missing) are mostly empty, and the ID is only a label. For the dropped columns we measured mutual information with the label on training rows only: about 0.002 for salary, 0.001 for telecommuting and 0.000 for benefits and department (as present/absent flags), against 0.013 to 0.029 for the main kept columns (industry, function, company logo, company profile). Location, as country, scored 0.018, which we left out for simplicity.
  • Fill gaps: missing categories become "Missing" (itself informative); missing text becomes empty. These fills use fixed values, not statistics learned from the data, so doing them before the split leaks nothing. The company profile text was dropped and replaced by a yes/no flag, has_company_profile, that records whether the posting has one. This flag turned out to be among the strongest features (mutual information 0.025, second only to industry).
  • One text field: title, description and requirements are joined into one column (called text_blob in the notebook), then turned into TF-IDF scores (5,000 words, English stop words removed, words in at least 5 postings: this drops typos and one-off words, and the cap keeps the matrix manageable), which up-weights words that are common in one posting but rare overall. Categories are one-hot encoded so that no false order is implied between them; flags pass through.
  • Split before learning: stratified 80/20 train/test split with seed 42 (12,758 train with 550 frauds; 3,190 test with 138 frauds). TF-IDF and encoders live inside a pipeline, so they are re-fit on training folds only and never see validation or test rows.
  • Feature checks (mutual information, random-forest importance, chi-square word scores) used training rows only, so the test set played no part in choosing features.

Baseline and methods

Baseline: always predict "genuine". It scores 95.7% accuracy but catches no fraud (recall 0), so any real model has to beat it on recall, F1 and PR-AUC rather than accuracy.

Model: logistic regression with class_weight='balanced', because fraud is rare. It suits sparse text features, trains fast, and each word gets a weight we can read, which powers the explanations on this page. We tuned the penalty (L1 or L2) and strength C (0.01 to 100) with 5-fold stratified cross-validation scored by PR-AUC. The best setting was L2 with C = 10.

Objectives and assumptions. Logistic regression fits one weight per feature by minimising a regularised log-loss (the penalty keeps weights small). It assumes the log-odds of fraud are a weighted sum of the features, which suits sparse TF-IDF text and gives a readable weight for every word. The random forest averages many decision trees trained on random samples of the data; it assumes no linear form and can pick up interactions between features, but its scores are harder to explain. The baseline needs no assumptions and sets the floor.

Comparison model: a random forest (200 trees, class-balanced, minimum leaf size 1 or 3 tuned) was tuned on the same folds to check whether a more complex model helps. All three models were scored with the same stratified 5-fold CV on the training set (mean ± standard deviation over folds):

Evaluation

Tuning and final testing are kept apart: the grid search used only the training set with 5-fold stratified CV (same folds for every model), and the test set was scored once at the end. Stratification keeps the fraud proportion approximately consistent across folds,keeps the 4% fraud rate in every fold.

Because only about 4% of postings are fraud, accuracy is misleading. We lead with PR-AUC (ranking quality for the rare class), recall (frauds caught) and precision (flags that are right), and report F1 and ROC-AUC as summaries. ROC-AUC can look high when negatives are plentiful (ours is 0.98), so PR-AUC is the main score. We used 5 folds as a common balance between a stable estimate and run time. Bootstrap intervals (1,000 resamples of the test set) show how uncertain the numbers are.

The 0.5 decision threshold was fixed before testing. The slider in Results is for understanding the trade-off, not for choosing a threshold on test data.

      • False alarms look like the fraud pattern. Only 37% have a logo and 30% a company profile, versus 83% and 85% of correctly passed genuine postings, and they are shorter (median 174 vs 245 words).
      • Missed frauds look ordinary. 42% have both a logo and a profile (caught frauds: 25%), so the model scores them low (median 0.15).
      • The threshold only helps borderline cases. Half of the false alarms score below 0.70: at threshold 0.7 they drop from 71 to about 36, but recall falls from 0.81 to 0.74. At 0.2 we would catch 8 more frauds but add about 120 false alarms.
      • Some mistakes are confident. 15 of the 71 false alarms scored above 0.9 and 8 of the 26 missed frauds scored below 0.1, so only an extreme threshold would change them; 38 of the 97 errors score between 0.3 and 0.7. The industry field was missing for 19 of the 71 false alarms and 8 of the 26 missed frauds.

      Representative cases (load them in Try it): false alarms "Human Resources" and "Comedy Ticket Sales Representative" (both scored 0.99 although genuine); missed frauds "Nursing & Therapy Positions- Home Care" and "Sir Awesome" (both scored about 0.01).

      These are associations, not causes, and 26 missed frauds is a small sample.

      Limitations

      • One dataset from one source, collected years ago; scammers change tactics, so results may not carry over to today's postings.
      • Only 138 test frauds: the intervals are wide (recall could be 0.75 to 0.87).
      • The model leans on logo and profile flags and on industry words (oil, gas, subsea), which may reflect how this dataset was collected rather than fraud itself.
      • A random forest tied logistic regression on ranking quality in CV, so the choice of logistic regression rests on recall at 0.5 and interpretability, not on a clear accuracy win.
      • Precision is about 0.6, so flags need human review. Duplicates were removed by exact text match; near-duplicates may remain.

      Conclusion

      Answer to the question: yes, to a useful but imperfect degree. Using only what is visible on a posting, the final model caught 81% of the fraudulent test postings (recall 0.81) with 61% of its flags correct (precision 0.61), and its test PR-AUC was 0.81 against 0.04 for the always-genuine baseline. A random forest tied it on ranking quality in cross-validation but caught far fewer frauds at the default threshold (35% against 73%), so we kept the simpler, explainable logistic regression. The model is a triage tool for human review, not a final judge: about 4 in 10 flags are false alarms, and the evidence rests on one dataset and 138 test frauds. Next steps: near-duplicate removal, adding country, and testing on newer postings.

      Team contributions

      Both team members carried out the preprocessing, which covered removing duplicate postings, dropping weak columns, building the TF-IDF and one-hot encoding pipeline, and making the stratified train/test split. Both also developed this website.

      Mahathi: logistic regression (the final model).

      Mahathi built and tuned the logistic regression. Class weighting was used because only about 4% of postings are fraudulent. The penalty (L1 or L2) and the strength C were tuned with 5-fold cross-validation scored by PR-AUC, which suits a rare class. The best setting (L2, C = 10) caught 73% of the frauds in cross-validation, with a precision of 0.58. On the held-out test set it caught 81%, with a precision of 0.61. A key limitation is that about 4 in 10 of its flags are false alarms, so its output needs human review. A small change shows the trade-off: lowering the threshold from 0.5 to 0.3 on the test set raises recall from 0.81 to 0.83 but lowers precision from 0.61 to 0.45.

      Samyuktha: random forest (the comparison model).

      Samyuktha built and tuned the random forest to test whether a more complex model would help. It used 200 class-balanced trees, and minimum leaf sizes of 1 and 3 were compared on the same cross-validation folds. It had the highest accuracy (0.971) but caught only 35% of frauds at the default threshold. Its PR-AUC (0.732) was within noise of the logistic regression (0.711), so the extra complexity did not clearly help. A key limitation is that it cannot be exported as a small set of weights to run in the browser, and its scores are harder to explain. A small change: raising the minimum leaf size from 1 to 3 lowered its cross-validation PR-AUC from 0.732 to 0.715, so the smaller leaf size worked slightly better.

      Reproduce

      1. Download fake_job_postings.csv from Kaggle (link above).
      2. Install the packages: pip install -r requirements.txt (scikit-learn 1.6.1).
      3. Run ES_335_ML_Project.ipynb top to bottom (random seed 42 everywhere). The last cell writes model.json and examples.json; the earlier test cell writes test_scores.csv and fraud_model.joblib.
      4. Preview the site: run python -m http.server in this folder and open localhost:8000.

      Everything is in the GitHub repository: notebook, split file (results/split_indices.csv) and all result tables.

      The raw dataset and API keys are not committed. Only load .joblib files you trust.
